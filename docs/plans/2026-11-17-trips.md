# Trips feature plan

Date: 2026-11-17

## Context

The map shows visited sites but not how they group into trips. The owner wants:

- a "Trips" list;
- per trip: highlight its sites, draw a line through them in visit order;
- animation: line draws itself, dots light up in order, map pans/zooms to follow;
- later (floated, not yet authorized): a timeline with play button, scrubber, per-year chart.

No trip data exists. Trips are inferred once from `visits.json` dates and commit groupings, reviewed by the owner, then stored as hand-curated data. No runtime inference.

## Trip rule (confirmed with owner)

- A trip has 2+ sites.
- Away trips: visit days with gaps of 2 days max form one trip.
- Exception: NYC Nov 14 + Nov 18 2022 merge into one trip (owner decision).
- Local (Boston-area) multi-site days count as trips. Each local day is its own trip; local days do not chain (we sleep at home between them).
- Single-site visits are not trips.
- `lecl` (Lewis & Clark NHT) is not in `parks.json`, so it has no coordinates and no marker. Omit it from trip data.

## UX recommendation

- **Entry:** 4th toolbar button "Trips" (route icon) in `src/index.html`, same pattern as Stats.
- **Sheet:** `createSheet` from `src/js/sheet.js`. Non-modal so the map stays live. Desktop: side card. Mobile: bottom sheet with snap points (same as the state park list), drops to the low snap during playback so the map is visible.
- **List view:** newest first. Row = name, date range, site count, state chips.
- **Trip view (same sheet):** back button, Play/Replay button, itinerary grouped by day with numbered stops. Tap a stop → open its park card (existing `clickedPoint` in `src/js/modal.js`). Deviation: no zoom to the stop in Phase 1.
- **Map in trip view:** non-trip markers and states dimmed (existing `.dimmed` pattern). Trip dots enlarged. Route line in the visited-green token, round caps, counter-scaled width.
- **Animation (Phase 2):** day-by-day camera. For each day: zoom to fit (previous stop + that day's stops), then draw that day's legs with `stroke-dashoffset`; each dot lights up when its leg finishes. End: zoom out to fit the whole trip. Any user pan/zoom/tap skips to the end state. `prefers-reduced-motion`: no animation, show the end state.
- **Deep link:** `#trip/<id>`.

## Phases (one PR each, per repo convention)

### Phase 1 — data, list, static route

- `src/data/trips.json`: `[{ id, name, stops: [{ parkCode, date }] }]`, data from the list above.
- `src/js/trips.js`: build the Trips button + sheet (list view, trip view), select/clear trip.
- `src/js/projection.js`: add pure `transformForBounds(bounds, width, height, {padding, minExtent, minScale, maxScale})`. Refactor `clickedMap` (`src/index.js:701`) to use it. `minExtent` stops a degenerate box (13 National Mall stops) from zooming to max.
- `src/index.js`: new `g.trip-layer` between states and markers; one `<path>` per leg from projected points; counter-scale `.trip-leg` stroke in the `zoom` handler (`src/index.js:139`); rebuild legs in `handleResize`; dim/highlight via classes; extend `isHighlightedDot` so trip dots keep the enlarged radius.
- `src/js/router.js`: `trip/<id>` in `parseHash`/`formatHash`, `model.trip`, `openTrip`/`closeTrip` callbacks. Trip and state zoom are mutually exclusive; park card can open over a trip.
- `src/css/map.css`: trip list, itinerary, route line, dimmed markers; light + dark tokens.
- Update the `add-park-visit` skill: when new visits form a trip under the rule above, append to `trips.json` and ask the owner to confirm order.
- Commit this plan as `docs/plans/2026-11-17-trips.md`.

### Phase 2 — animation and camera

- `src/js/trip_player.js`: sequencer over days/legs using D3 transitions; camera via `transformForBounds` + `zoom.transform`; cancellable; duration scales with leg count, capped.
- Play/Replay/Skip controls in trip view; `aria-live` announcements per day via `src/js/live.js`.

### Phase 3 — timeline (proposed, needs your go-ahead)

- "Timeline" mode: scrubber from first visit (2017-08-13) to today, play button, markers appear as their first visit date passes, mini per-year bar chart above the slider (reuse year data from `calculateStats` in `src/js/statistics.js`). Reuses the Phase 2 player/camera.
